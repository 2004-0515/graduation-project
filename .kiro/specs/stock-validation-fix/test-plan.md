# 手动测试计划

## 测试环境准备

### 1. 启动服务

```bash
# 终端1: 启动后端服务
cd backend
mvn spring-boot:run

# 终端2: 启动前端服务
cd frontend
npm run dev
```

### 2. 访问地址

- 前端: http://localhost:5173
- 后端: http://localhost:8080

### 3. 测试账号

| 用户名 | 密码 | 说明 |
|--------|------|------|
| admin | 123456 | 管理员账号 |
| zhangsan | 123456 | 普通用户 |

### 4. 测试数据准备

需要准备以下测试商品：
- 商品A: 库存 > 5（测试正常流程）
- 商品B: 库存 = 1-3（测试库存不足）
- 商品C: 库存 = 0（测试售罄状态）

**如何准备**:
1. 登录管理员账号
2. 进入商品管理页面
3. 修改商品库存为测试所需值

## 测试场景

### 场景1: 库存充足 - 正常流程

**前置条件**:
- 已登录
- 商品库存 >= 10

**测试步骤**:

1. **测试加入购物车**
   - [ ] 访问商品详情页
   - [ ] 数量选择器默认值为 1
   - [ ] 点击"加入购物车"按钮
   - [ ] 验证：显示"已加入购物车"成功消息
   - [ ] 验证：购物车数量增加

2. **测试立即购买**
   - [ ] 访问商品详情页
   - [ ] 数量选择器设置为 2
   - [ ] 点击"立即购买"按钮
   - [ ] 验证：跳转到结账页面
   - [ ] 验证：结账页面显示正确的商品和数量

3. **测试数量调整**
   - [ ] 访问商品详情页
   - [ ] 点击 + 按钮增加数量到 5
   - [ ] 验证：数量正确增加
   - [ ] 点击 - 按钮减少数量到 3
   - [ ] 验证：数量正确减少
   - [ ] 手动输入数量 7
   - [ ] 验证：数量正确更新

**预期结果**: 所有操作正常，无错误消息

## 测试工具

### 浏览器开发者工具

1. **Network 面板**
   - 监控 API 请求
   - 验证请求参数
   - 检查响应数据

2. **Console 面板**
   - 查看错误日志
   - 验证警告消息

3. **Elements 面板**
   - 检查按钮的 disabled 属性
   - 验证输入框的 max 属性
   - 检查元素的样式

### 测试技巧

1. **清除缓存**: 每次测试前清除浏览器缓存
2. **使用隐身模式**: 避免缓存和扩展干扰
3. **记录截图**: 对于失败的测试，截图保存
4. **记录网络请求**: 使用 Network 面板记录 API 调用

## 测试完成标准

所有10个场景的所有测试步骤都必须通过，才能标记为"测试完成"。

如果发现任何问题：
1. 详细记录问题
2. 提供复现步骤
3. 附上截图或错误日志
4. 反馈给开发人员
5. 修复后重新测试

**重要提示**: 
- 不要跳过任何测试场景
- 每个测试步骤都要仔细验证
- 发现问题立即记录
- 测试完成后填写 manual-test-results.md
