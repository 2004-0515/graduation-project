# 仪表盘测试数据丰富计划

## 目标
为管理员仪表盘生成完整、逻辑清晰、无冲突的测试数据，确保所有图表都能正常显示。

## 数据生成策略

### 1. 时间分布策略
- **最近7天**: 每天3-5个订单（共25-35个订单）
- **最近30天**: 前23天每天1-3个订单（共23-69个订单）
- **历史数据**: 30天前的订单（用于"全部"时间范围对比）

### 2. 订单状态分布
确保各种状态都有足够数据：
- 待付款(0): 5个订单
- 待发货(1): 8个订单
- 待收货(2): 10个订单
- 已完成(3): 60个订单
- 已取消(4): 5个订单
- 退款中(5): 2个订单
- 申请取消中(6): 3个订单

### 3. 商品分类销量分布
确保所有12个分类都有销售数据：
- 数码电子: 30%
- 家用电器: 20%
- 服装鞋包: 15%
- 美妆护肤: 12%
- 食品饮料: 10%
- 图书文娱: 5%
- 其他分类: 8%

### 4. 用户注册时间分布
- 最近7天: 3个新用户
- 最近30天: 10个新用户
- 历史用户: 10个用户

### 5. 数据完整性保证
- 所有订单必须有完整的订单项
- 所有订单项必须有seller_id和seller_name
- 已支付订单必须有payment_time
- 已发货订单必须有shipping_time
- 已完成订单必须有end_time
- 所有金额字段不为NULL
- 所有地址信息完整

## 数据生成详情

### 订单数据生成规则
1. 订单号格式: ORD + YYYYMMDD + 序号(4位)
2. 订单金额范围: 50-15000元
3. 每个订单1-3个商品
4. 订单时间按逻辑顺序:
   - created_time < payment_time < shipping_time < end_time
   - 时间间隔合理(支付5-30分钟,发货1-2天,收货3-7天)

### 用户分配规则
- 用户ID 2-20 (排除admin)
- 每个用户至少有1个订单
- 活跃用户(10-15)有多个订单
- 新用户(16-20)订单较少

### 商品分配规则
- 商品ID 1-51
- 热销商品(1-10)出现频率高
- 普通商品(11-40)正常频率
- 冷门商品(41-51)偶尔出现

### 卖家分配规则
- seller_id=1 (admin): 平台自营,占30%
- seller_id=2-10: 活跃卖家,各占5-10%
- seller_id=11-20: 普通卖家,各占1-3%

## SQL文件结构

```sql
-- 1. 清理现有测试数据
-- 2. 生成用户注册数据(更新created_time)
-- 3. 生成历史订单(30天前)
-- 4. 生成最近30天订单
-- 5. 生成最近7天订单
-- 6. 生成今日订单
-- 7. 更新商品销量
-- 8. 生成评价数据
-- 9. 生成购物车数据
-- 10. 生成通知数据
-- 11. 验证数据完整性
```

## 预期效果

执行SQL后,仪表盘应该显示:
- **销售趋势图**: 清晰的7天趋势线,有起伏
- **订单状态分布**: 饼图显示所有状态,已完成占比最大
- **分类销量TOP5**: 横向柱状图显示前5个分类
- **今日数据**: 有3-5个今日订单,收入5000-20000元
- **待处理订单**: 10-15个
- **库存预警**: 5-10个商品

## 数据一致性检查

生成数据后必须通过以下检查:
- [ ] 所有订单项都有seller_id和seller_name
- [ ] seller_id在1-20范围内
- [ ] 商品ID在1-51范围内
- [ ] 用户ID在1-20范围内
- [ ] 订单状态在0-6范围内
- [ ] 支付状态在0-2范围内
- [ ] 已支付订单(status>=1)的payment_status=1
- [ ] 已完成订单(status=3)有end_time
- [ ] 订单金额 = 订单项金额之和
- [ ] 无孤立数据(外键完整性)
